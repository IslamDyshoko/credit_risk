# Credit Risk Scoring

Проект по разработке системы оценки кредитного риска на основе алгоритмов машинного обучения. Цель — прогнозирование вероятности возникновения серьёзной просрочки по кредиту и исследование методов принятия решений с учётом статистических и экономических критериев.

## 1. Описание данных

В проекте используется датасет **VUB Credit Scoring**, содержащий информацию о заёмщиках румынской небанковской финансовой организации (Non-Banking Financial Institution, NBFI).

Источник данных: [Empulse — VUB Credit Scoring](https://empulse.readthedocs.io/en/latest/guide/datasets/vub_credit_scoring.html).

Основные характеристики:
- Количество наблюдений: 18 917.
- Количество признаков: 16.
- Количество проблемных заёмщиков: 3 206.
- Целевая переменная: наличие серьёзной просрочки платежа (45 и более дней).

Датасет также содержит информацию о стоимости ошибочных решений, которая позволяет исследовать экономическую эффективность моделей кредитного скоринга.

### Описание признаков

| Признак | Тип | Описание |
|---|---|---|
| `v1`–`v8` | Categorical | Анонимизированные категориальные признаки |
| `has_fico` | Binary | Наличие кредитного рейтинга FICO |
| `business_channel` | Categorical | Канал выдачи кредита |
| `fico_score` | Numeric | Кредитный рейтинг FICO |
| `loan_amount` | Numeric | Стандартизированная сумма кредита |
| `monthly_income` | Numeric | Стандартизированный ежемесячный доход |
| `age` | Numeric | Возраст заёмщика |
| `gearing_coefficient` | Numeric | Коэффициент долговой нагрузки |
| `max_gearing_ratio` | Numeric | Максимально допустимый коэффициент долговой нагрузки |

**Примечание:** `v1`–`v8` анонимизированы, поэтому их предметная интерпретация недоступна. Часть числовых признаков стандартизирована.

## 2. Постановка задачи

Основная задача — бинарная классификация заёмщиков по вероятности возникновения серьёзной просрочки.

Целевая переменная:
- `1` — заёмщик допустил просрочку на 45 и более дней;
- `0` — серьёзная просрочка отсутствует.

Дополнительная задача — исследование экономической эффективности решений модели с использованием информации о стоимости ошибок классификации.

## 3. Методология

### 3.1. Exploratory Data Analysis (EDA)

Исследование структуры и статистических свойств данных:
- анализ распределения целевой переменной;
- анализ типов признаков и их распределений;
- исследование пропущенных значений;
- анализ выбросов;
- исследование взаимосвязей между признаками;
- анализ взаимосвязей признаков с целевой переменной.

### 3.2. Feature Engineering

Исследование возможностей улучшения признакового пространства:
- преобразование категориальных признаков;
- обработка пропущенных значений;
- создание новых признаков;
- анализ полезности существующих признаков.

Применение Feature Engineering будет определяться результатами EDA и последующих экспериментов.

### 3.3. Статистическая постановка задачи

Разработка и сравнение моделей бинарной классификации.

Рассматриваемые подходы и алгоритмы:
- Logistic Regression;
- Random Forest;
- Gradient Boosting;
- CatBoost / LightGBM.

Оценка качества моделей с использованием статистических метрик классификации и оценки вероятностных прогнозов.

### 3.4. Экономическая постановка задачи

Исследование кредитного скоринга с учётом стоимости ошибочных решений.

Основные направления:
- анализ стоимости False Positive и False Negative;
- cost-sensitive learning;
- подбор порога классификации с учётом ожидаемых потерь;
- сравнение статистически и экономически оптимальных решений.

### 3.5. Интерпретация моделей

Анализ факторов, влияющих на прогнозы:
- Feature Importance;
- SHAP;
- исследование влияния отдельных признаков на риск дефолта.

### 3.6. Результаты

Сравнение моделей и подходов:
- качество классификации;
- калибровка вероятностей;
- экономические потери;
- интерпретируемость;
- итоговое сравнение решений.

### 3.7. Развёртывание

Создание программной обёртки для использования обученной модели:
- сохранение и загрузка модели;
- обработка входных данных;
- получение прогнозов;
- API или пользовательский интерфейс;
- контейнеризация с использованием Docker.

Состав данного раздела будет зависеть от выбранного варианта реализации.
